# GOC — Experimental C++-like Compiler + VM

GOC (GreyOne Compiler) is an end‑to‑end compiler pipeline written from scratch in C++17: lexer → parser → AST → bytecode → stack‑based virtual machine. It compiles a practical C++‑like subset and executes it on a custom VM with debugging and disassembly support. This is a **beta**/learning project, but the pipeline is already functional for real toy programs.

## Highlights

- Full pipeline: tokenize → parse → generate bytecode → run on a VM
- Handwritten recursive‑descent parser with AST dumping
- Stack‑based VM with disassembly, debug tracing, and memory/stack dumps
- Function support with name mangling for overloads
- Floating‑point support via a small FPU stack
- String table + `std::cout` chains for output

## Quick start

Build:

```bash
cmake -S goc -B goc/build
cmake --build goc/build
```

Run the regression suite:

```bash
ctest --test-dir goc/build --output-on-failure
```

Compile and run an example:

```bash
./goc/build/goc examples/euler.cpp -o examples/euler.bin --dump-bytecode
./goc/build/vm examples/euler.bin --disassemble
./goc/build/vm examples/euler.bin
```

Expected output (approx):

```
2.718280
```

## Usage

### Compiler (`goc`)

```bash
./goc/build/goc [options] <input file>
```

Options:

- `-h`, `--help` — help
- `-o`, `--output <file>` — write bytecode to file (default: `<input>.bin`)
- `-v`, `--verbose` / `-q`, `--quiet` — verbose toggles
- `-s`, `--stats` — token statistics only
- `--stage <lex|parse|codegen>` — stop after a stage
- `--dump-tokens` — dump tokens
- `--dump-ast` — dump AST
- `--dump-bytecode` — dump generated bytecode

### Virtual machine (`vm`)

```bash
./goc/build/vm [options] <bytecode file>
```

Options:

- `-h`, `--help` — help
- `-d`, `--debug` — trace execution
- `-s`, `--stats` — execution statistics
- `--disassemble` — disassemble bytecode and exit
- `--dump-stack` — dump stack after execution
- `--dump-memory` — dump memory after execution

## Language subset (what works today)

The parser recognizes a wide set of C++ constructs, but the **code generator targets a smaller executable subset**. Currently supported in codegen:

- Variables, assignments, arithmetic, and comparisons
- `if`, `while`, `for`, and `return`
- Functions + overload name mangling
- Arrays/pointers with basic `new` allocation
- `std::cout << ...` chains and `std::cin >> ...`
- Float/double expressions via the FPU stack

## Status & limitations

This is a **beta** compiler. Lexical scopes and unresolved-name checks are implemented, but there is no complete semantic-analysis pass (for example, full type checking or advanced error recovery). Unsupported code-generation paths fail compilation instead of silently emitting placeholder values.
